# ED / EE — density through hierarchy, not decoration

Date: 2026-08-12
Scope: Rurubu WEDDING only

## Lesson
A dense Japanese travel-magazine page does not need more UI modules. Density can come from stronger differences in scale, tighter information grouping, overlapping photography, and short editorial rules.

### Back-cover chronology
If a travel-log/timeline looks like a presentation infographic, first remove decorative connectors. A 3×2 set of events with larger dates, compact labels, and thin vertical color rules gave ED a faster reading order and more print-native density than EC's dashed zig-zag route.

Use route lines only when the route itself conveys meaningful sequence or geography. Do not keep them merely because the theme is travel.

### Photo-led memory section
At thumbnail scale, force a clear image ratio:

`dominant photo > support photo > accent photo`.

EE improved DZ by making the first memory image carry the section, using a tall second image for vertical counter-rhythm, and a smaller tilted third image as an accent. Keep captions attached to their photographic role rather than collecting them into equal cards.

### Contrast escalation
Subtraction remains default, but direct text on a busy image is not automatically more authentic. Use the smallest sufficient device:

`direct type → short rule → edge-attached caption strip → larger field only if absolutely necessary`.

The EE third-photo caption strip is acceptable because it is thin, attached to the photo, unshadowed, and visually subordinate.

### QA lesson
Actual-size screenshot QA and structure QA catch different failures. ED visually improved before structure found six year/label text-box intersections. EE visually improved before structure exposed an inherited Q1 collision on the other page. A clean-looking render is not evidence of semantic/structural cleanliness, and collision=0 is not evidence of rendered glyph quality. Require both.
