# Wedding Design Learning / Feedback Log append — Rurubu JC Outer

Date: 2026-08-21
Scope: Rurubu WEDDING only

## Visible problem

IU front cover was photographically strong but still read mainly as one large hero plus one large lower support image. The hierarchy was clean, yet comparatively brochure-like after the newer V6 spreads became denser and more editorial.

## Principle tested

Photo-role variety can create stronger magazine rhythm only when each added image has a truthful semantic owner.

## Bounded experiment

- duplicated IU to JC `2148:2`;
- retained hero, masthead, native cover text and lower dining photo;
- added one smaller physical-postcard-like image beat;
- first café-image variant rejected because it was decorative density without a coherent Feature 02 role;
- replaced it with existing skyline image and moved existing native Feature 02 chronology caption onto it;
- kept native text, existing image hashes and rollback.

## Evidence / outcome

- 500 px whole outer: PASS and stronger than IU.
- 1400 px reading: PASS.
- native 1587×1123: PASS.
- visible native text 35; IMAGE fills 5; intersections 0; 18 px safe risks 0.

Final status: `ADOPTED / VERIFIED_LOCAL`, JC `2148:2` preferred, IU `2124:2` hidden rollback.

## Rejected state

The initial café postcard was explicitly rejected. Surface richness alone was insufficient because the image had no truthful semantic ownership relative to the nearby Feature 02 chronology caption.

## Next application

Do not repeat postcard rotation/border as a style token. Re-run the six-spread comparison and apply the semantic-photo-ownership principle only where a distinct role actually needs another visual beat.
