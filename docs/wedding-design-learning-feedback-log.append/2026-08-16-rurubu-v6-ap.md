## Visible problem

The current V6 AI chronology was technically safe but still read as six separate photo/event modules. The Story page also left a visibly inactive lower field. At thumbnail scale these weaknesses made the spread feel like a designed template rather than a Japanese travel-magazine feature.

## Principle / hypothesis

1. A chronology can remain fully editable without giving every event an equal visual/photo container.
2. Native text can carry the complete chronological sequence while fewer, stronger image anchors create editorial mass.
3. Dead lower-page space should first be repaired through existing photo scale/overlap and reading rhythm before adding cards or decorative filler.

Expected improvement: clearer chronological reading, less implicit grid/dashboard rhythm, stronger page-to-page photo hierarchy, and a denser travel-magazine spread without sacrificing editability.

Regression risk: removing too many event images could make the chronology feel like a plain list; enlarging photos can expose low-resolution sources; a dark final band can become UI-like if it does not genuinely close the story.

## Learning / next application

The useful transferable hypothesis is not “use a vertical rail” and not “remove event photos.” It is:

> When repeated sequential content reads as a grid of equal modules, independently test whether native text can carry the full sequence while a smaller number of strong visual anchors provide page-level hierarchy.

For Rurubu specifically, continue judging the whole spread before adding decoration. Keep V7 HOLD until V6 is genuinely coherent and final-content/print gates are closed.
