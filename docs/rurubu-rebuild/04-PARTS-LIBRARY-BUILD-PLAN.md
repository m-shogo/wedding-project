# Rurubu WEDDING — Parts Library Build Plan

Status: `REFERENCE_FIRST_PARTS_PLAN`

Source vocabulary: canonical Drive reference `12ppT-SV-8OmOgz_a0MuhrkT3gNOOKsY3`.

## Rule

Do not generate decorative assets indiscriminately. Build semantic families that correspond to observed reference roles and planned page manuals.

Each family needs enough silhouette variation to avoid component-clone pages.

---

## TIER A — identity / titles

### A1. Mini Rurubu-like brand block
Role: small persistent magazine identity marker.
Need: 2–3 size/stack variants.
Use: cover, journey opener, occasional small reprise only.

### A2. WEDDING hero wordmark
Role: cover first-read.
Need: 2–3 compositions, including horizontal and compact.
Traits: thick rounded letterform, hot pink core, white keyline, yellow/cyan support/shadow.

### A3. Page-title family
Roles:
- Journey/Map
- Profile
- Memories
- Venue Guide
- 1DAY Schedule
- Q&A
- Guest Message
Need: 7 distinct but related silhouettes.
Do not force every title into the same ribbon.

---

## TIER B — editorial labels

Need families for:
- coverline label;
- ribbon label;
- recommendation burst;
- chapter chip;
- handwritten note plate;
- luggage-tag label;
- `Special Thanks`/utility note marker;
- numbered Q labels;
- schedule time markers.

Target: 10–16 useful variants, not 16 color swaps of one shape.

---

## TIER C — travel objects

Observed/high-value roles:
- airplane, 3 orientations;
- suitcase/luggage cluster, 2–3 variants;
- passport;
- boarding pass/tickets;
- camera, 2 angles/scales;
- globe;
- sunglasses;
- postcard;
- map pin;
- signpost;
- postmark/date stamp;
- route line/airplane route.

Build isolated transparent assets where possible.

---

## TIER D — tropical framing

Need:
- upper-left corner foliage/flowers;
- upper-right corner;
- lower-left corner;
- lower-right corner;
- narrow horizontal flower cluster;
- single hibiscus/plumeria-like blossoms;
- isolated tropical leaf;
- palm silhouette/leaf.

These should create edge tension, not a uniform floral border.

---

## TIER E — photo treatment system

Need replaceable photo-frame shells:
- portrait polaroid;
- landscape polaroid;
- small snapshot;
- postcard;
- taped-corner card;
- white-keyline loose frame;
- circular crop support;
- organic/cutout support;
- vertical narrow gallery frame.

Critical: frame and photo source must remain separate in Figma.

---

## TIER F — handwritten / micro-discovery

Need:
- heart ×3 styles;
- curved arrow ×3;
- hand underline ×2;
- rough circle ×2;
- sparkle/star ×3;
- wavy route/doodle ×2;
- short scribble markers;
- speech bubbles ×3 silhouettes.

Use to humanize and guide, not to fill every gap.

---

## TIER G — utility / information shells

Need native-text-friendly shells for:
- profile fact row;
- story milestone/date;
- destination number;
- venue-data subheading;
- schedule time marker;
- Q-number marker;
- answer field;
- dress-code/color-swatch field;
- hashtag/social participation label;
- small map legend.

The shell can be reusable. The factual text must remain native/editable.

---

## TIER H — tactile paper layer

Need subtle supports:
- warm cream paper;
- faint postcard lines;
- tape strip;
- slightly imperfect ink stamp texture;
- very subtle grain/halftone.

Do not fake quality with heavy texture.

---

# Part metadata

Every reusable part should record:
- semantic family;
- role;
- variant;
- source type: existing/generated/drawn;
- reference relationship;
- intended physical max size;
- transparency requirement;
- text embedded yes/no;
- editable text fallback required yes/no;
- page candidates;
- QA state.

Suggested states:
`NEEDED → SEARCHED → CANDIDATE → VISUAL_QA → FIGMA_READY → PRINT_QA → APPROVED`.

---

# Generation boundary

Prefer generation for isolated decorative/display assets.

Do not generate final raster content containing:
- long Japanese body copy;
- names/date/time likely to change;
- profile facts;
- Q&A answers;
- venue facts;
- guest instructions.

Whole-page generation is allowed only as a visual exploration/reference target, never as the sole editable production master.

---

# Build order

1. title/identity family;
2. photo-frame system;
3. tropical corner family;
4. travel-object anchors;
5. labels/number/time markers;
6. handwritten micro-parts;
7. route/map utilities;
8. paper texture/support.

Reason: title + photo behavior + edge framing produce most of the reference feeling. Do not waste time generating minor stickers before these are strong.
