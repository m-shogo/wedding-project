# Rurubu WEDDING — New 8-Page Architecture

Status: `REFERENCE_FIRST_DRAFT_AUTHORITY`

This page map is derived from the canonical reference image and the wedding-booklet use case. It intentionally does not inherit the legacy V10 map.

## P01 — COVER
Purpose: sell the booklet instantly as a joyful travel magazine.
Primary grammar: oversized title + hero couple + stacked coverlines + tropical edge framing.

## P02 — OUR JOURNEY MAP
Purpose: introduce the wedding/travel concept and the couple's journey as a geographic adventure.
Primary grammar: map/route hero + scattered travel snapshots + luggage/tickets + date/venue utility footer.

## P03 — PROFILE + OUR STORY
Purpose: introduce both people and provide a compact relationship chronology.
Primary grammar: two portraits + native profile facts + narrow story rail + favorite-things strip.

## P04 — OUR MEMORIES
Purpose: let guests browse memorable trips/places through photography.
Primary grammar: uneven polaroid/postcard collage + small handwritten notes + travel objects.

## P05 — VENUE GUIDE
Purpose: explain the wedding venue like a Rurubu destination guide.
Primary grammar: venue hero image + detail gallery + short guide copy + illustrated/simplified venue map.

## P06 — WEDDING 1DAY SCHEDULE
Purpose: make the wedding-day flow practical and fun to scan.
Primary grammar: strong vertical time spine + small visual strip + dress-code/guest utility side column.

## P07 — COUPLE Q&A
Purpose: make guests smile and learn details that do not fit the profile page.
Primary grammar: six questions with a clear repeated base structure softened by varied labels, thematic objects and edge decoration.

## P08 — MESSAGE / PARTICIPATION / CLOSING
Purpose: close with guest participation rather than a passive generic back cover.
Primary grammar: large calm message area + postcard/postmark language + photo-sharing/photo-contest utility + dense travel souvenir closing cluster.

---

# Why this sequence works

`impact`
→ `travel concept`
→ `know the couple`
→ `browse memories`
→ `understand the venue`
→ `understand today's flow`
→ `playful discovery`
→ `participate and close`.

This creates deliberate alternation between emotional/photo-heavy pages and practical/reading pages.

---

# Content-fit rule

This architecture is not protected for its own sake. Before final Figma assembly, every page must pass a content-fit check:

- do we have meaningful real content for the page?
- does the page help an actual guest?
- is another page overloaded because this page is underused?
- can the role be improved without breaking whole-book rhythm?

If a page fails those questions, change the new architecture. Do not restore a legacy role merely because old Figma already contains it.
