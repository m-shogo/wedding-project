## NRSL — Family-scale template repetition gate

State: `VERIFIED_CROSS_ITEM → PROMOTED_PROJECT_RULE`

### Visible problem

Several independently polished wedding artifacts could pass their own thumbnail / reading / actual-size review and still look too similar when the suite was viewed as a family. The repeated signal was not identical component reuse; it was repeated **dominant visual grammar** across unrelated physical objects — especially dark saturated fields, the same coral/lagoon/yellow relationship, large rounded sweeps/capsules, and similar hero-motion composition.

This can make genuinely separate print items read like one AI/template system with different copy, even when each item is locally attractive.

### Root cause

Local visual QA asks whether one artifact is coherent, legible, attractive and physically plausible. It does not by itself detect whether the same macro grammar has become a default across unrelated items.

The repeated-template feeling emerges one level higher from combinations such as:

- the same dominant background behavior;
- the same oversized primitive family;
- the same movement direction / crop rhythm;
- the same accent-color roles;
- the same hero-to-detail ratio;
- the same “large abstract field + native copy” solution regardless of physical object role.

Changing only colors or small ornaments does not solve this fingerprint.

### Promoted project rule

**A local `SELLABLE_VISUAL_QA_PASS` does not exempt an item from a suite/family thumbnail audit.**

For each materially different physical wedding artifact:

1. judge the item locally at whole / reading / actual-size scale;
2. also view it against the currently selected suite family at thumbnail scale;
3. compare dominant physical/compositional grammar, not merely exact components;
4. if unrelated items repeat the same macro grammar strongly enough to look templated, reopen family-fit even when local quality remains high;
5. if reopening is required, derive a new blank-frame direction from the item's own physical role — booklet, baggage tag, timetable sheet, postcard, field note, wayfinding sign, writing card, etc. — rather than performing a palette swap;
6. keep previous production as rollback and comparison evidence;
7. only promote when the new item-specific grammar preserves or improves local usability while materially reducing family-template repetition.

### What this rule does NOT mean

It is not a requirement to make every artifact visually unrelated.

Preserve intentional family resemblance through appropriate constants such as:

- overall warmth / celebratory tone;
- Japanese-first editorial craft;
- typographic quality and optical alignment;
- travel / journey emotional language when semantically appropriate;
- print-quality discipline;
- factual editability / semantic placeholders;
- coherent production finish.

Vary the **dominant physical and compositional grammar**, not every token.

### Regression risk

Over-correcting can create a random portfolio with no wedding-family coherence. A redesign also fails if novelty reduces scanability, writing usability, actual-size readability or physical credibility.

Therefore the family-diversity gate is subordinate to item function and print QA. Difference is valuable only when the new solution remains as usable and polished as the retained Current.

### Failure fingerprint

`F-NRSL-FAMILY-SCALE-MACRO-GRAMMAR-REPETITION`

Trigger when multiple unrelated artifacts independently pass local QA but repeat enough of the same dominant background / oversized shape / motion / palette-role system that the suite reads as one reskinned component family.

Do not retry with another color swap, another small badge, or a different arrangement of the same rounded sweeps. Method-switch to a blank-frame physical-object grammar.

### Cross-item receiving rule

Next receiving items should be audited in progression order. Only reopen items where actual family-scale repetition is visible; do not redesign healthy distinct items just to create activity.
