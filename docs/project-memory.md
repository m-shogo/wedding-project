# Project Memory

このリポジトリは、結婚式動画制作をメインにしつつ、結婚式全体のコンセプト、内容、判断、好みを覚えるための場所でもある。

## 目的

- 毎回同じ説明をしなくて済むようにする。
- コンセプト、世界観、素材判断、BGM判断、演出判断を残す。
- 動画以外の相談も、動画の世界観や結婚式全体に関係するものは記録できるようにする。
- Gitを、制作の履歴と記憶として使う。

## メインとサブ

メイン:

- オープニングムービー
- プロフィールムービー
- 紹介ムービー、その他動画
- AI背景素材
- BGM、テロップ、編集指示

サブ:

- 招待状、席次表、しおり、返礼品
- 会場演出
- コピー、挨拶文、コメント
- テーマ、色、雰囲気、ゲスト体験

サブの相談も受ける。ただし、動画の世界観と矛盾しないように扱う。

## 記録するもの

- 決めたこと
- 迷っていること
- 不採用にした理由
- 好きな方向性
- 避けたい方向性
- 参考にしたもの
- 次にやること

## 記録先

- 全体方針: `docs/01_brief.md`
- 世界観: `docs/02_style-bible.md`
- テーマ変更: `docs/theme-switching.md`
- 素材と情報: `docs/materials-todo.md`
- 作業状態: `docs/task-board.md`
- 判断ログ: `docs/decisions/`
- テキスト案: `08_texts/`
- 全ウェディングFigma制作正本: `docs/wedding-figma-production-system.md`
- 全ウェディング生成素材メモリ: `docs/wedding-asset-generation-memory.md`
- 生成素材証拠台帳テンプレート: `docs/templates/wedding-generated-asset-register.csv`

## 運用ルール

- 重要な好みや判断が出たら、該当ドキュメントに残す。
- 迷った理由は `docs/decisions/` に短く残す。
- 写真、動画、音源などの実ファイルは原則Gitに入れない。
- Gitには、ログ、判断、構成、プロンプト、編集指示を残す。
- 動画以外の内容も、結婚式全体のコンセプトに関係するなら記録してよい。

## 全ウェディングFigma制作の恒久方針

るるぶV5だけでなく、V6、パスポート冊子、航空券風エスコートカード、ミンティア切符、招待状、席札、サイン、マップ、返礼品ラベルなど、今後Figmaで作る結婚式制作物すべてに以下を適用する。

- Figma操作量より、編集デザイン・日本語文字組み・情報階層・印刷物としての説得力を優先する。
- 作業前に `docs/wedding-figma-production-system.md` を読む。
- ライブFigma、Drive再確認、証拠台帳を古いチェックリストや会話記憶より優先する。
- native text、semantic node、非破壊クロップ、rollbackを維持する。
- 画像生成、Drive保存、Figma配置、品質合格、印刷準備を別状態として扱う。
- 変更後は全体、ページ、実寸細部の3段階でスクリーンショットQAする。
- カード、バッジ、角丸、影、グラデーションを増やす前に、主従と余白を直し、削除を試す。
- 最終印刷物は正式テンプレート、塗り足し、断裁、折り、解像度、PDFプリフライト、物理校正を通す。

## 生成素材の恒久方針

- 作業前に `docs/wedding-asset-generation-memory.md` と対象アイテムの台帳を読む。
- 必ず役割、縦横比、構図、余白、人物ルール、禁止物、Drive保存先を定義してから生成する。
- 採用画像は `生成 → 目視QA → Drive保存 → Drive再確認 → Figma派生画像 → Figma配置 → スクリーンショットQA → Git記録` まで進める。
- チャットや一時ローカルに画像があるだけではプロジェクト素材として完了にしない。
- 高品質原本とFigma転送用派生画像を分け、派生画像で原本を上書きしない。
- 新郎新婦、家族、友人、犬は本番では実写真・実動画を中心にする。
- 架空の生成人物を本人として見せない。ダミー人物は後ろ姿、遠景、手元など本人と誤認されにくい構図にする。
- 文字、数字、ロゴ、看板、ウォーターマークは画像に焼き込まず、原則Figmaのnative text/vectorで作る。
- 新しいclean-room版は、知識と工程は継承しても、前版の生成写真、image hash、hero構図、crop、card geometryを自動流用しない。

## 学習と改善

- ミスや不採用変更は、観察、原因、一般化できる原則、工程変更、実変更、検証の順で記録する。
- 同じ失敗を二度繰り返さないため、再利用できる教訓は正本へ昇格する。
- 一度の曖昧な好みだけでルールを増やしすぎず、複数の証拠や明確な編集理由を確認する。
- 今回のるるぶV5/V6で得た雑誌デザイン、Drive-first、Figma QA、素材証拠管理の知識は、今後の結婚式制作物すべてへ適用する。
