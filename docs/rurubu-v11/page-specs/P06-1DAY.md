# P06 — 1DAY

Status: `CANONICAL_PAGE_MANUAL`
Role: `1DAY / WEDDING ITINERARY`
Editorial metaphor: `travel-magazine model course`

## PAGE JOB
Let guests understand the day's sequence quickly while the page still feels festive, visual and magazine-like rather than like a timetable sheet.

## READING PATH
1. FIRST READ — `1DAY スケジュール` title.
2. SECOND READ — chronological time/route spine.
3. THIRD READ — ceremony/reception/key-event highlights.
4. USEFUL INFO — dress code / special note / practical side feature if confirmed.
5. MICRO DISCOVERY — icons, food/cake/rings/venue visuals, small floral/travel accents.

## ZONE MAP
- top 0–18%: page title.
- left/center 16–94%: main chronological spine with 5–8 confirmed events.
- right 22–80%: visual utility cluster such as dress code / cake / table / special thanks.
- lower 78–100%: closing event/visual reward + small note.

The main sequence and side feature should visually interlock; do not create two disconnected dashboard columns.

## TIME PLAN
Each event uses:
- native time label;
- native event name;
- optional small semantic icon;
- optional short note.

Repeated time labels may share one visual system because chronology is a legitimate repetition. Special milestones may be enlarged selectively.

## IMAGE PLAN
- `P06_VISUAL_HERO`: one stronger wedding-day visual such as cake/table/venue/detail, replaceable if photographic.
- `P06_SUPPORT_01..03`: 1–3 smaller support images/illustrations.
- illustration may be composed art when it is not claiming to be a real photo/fact.

## PARTS
- 1DAY title plate;
- chronological route/spine;
- time labels × confirmed event count;
- event icons;
- one utility feature label (`Dress Code`, `Special Thanks`, etc.) only if real content exists;
- 1–3 image frames;
- tropical/title-support cluster ×1–2;
- small celebratory objects.

## COLOR JOBS
- dominant: cream/paper or light cyan support;
- sequence structure: blue/deep teal;
- selected time highlights: pink/coral/yellow;
- body/facts: dark ink.

Do not assign a random saturated color to every event.

## OVERLAP
- route may visually pass behind one support image/frame;
- one event icon can sit on a route node;
- side visual may intrude slightly into itinerary territory to prevent two-column UI separation;
- title flora may bridge across upper zones.

## EDITABILITY
Native:
- all times;
- event names;
- dress-code facts;
- special-thanks copy;
- practical notes.

Replaceable:
- photographic support visuals.

Composed:
- route art;
- event icons;
- title;
- decorative illustrations/frames.

## FORBIDDEN
- spreadsheet/table appearance;
- fake transit-map complexity;
- invented or assumed schedule times;
- every event as an equal rounded card;
- side utility presented as an unrelated software panel;
- tiny time text to fit decoration.

## QA
Pass when the chronological sequence can be understood in under 10 seconds, all times remain editable, the side feature adds a visual reward without breaking sequence, and the page cannot be mistaken for a timetable/dashboard UI.
