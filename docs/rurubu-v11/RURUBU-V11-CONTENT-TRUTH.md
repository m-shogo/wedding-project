# Rurubu WEDDING V11 — Content Truth Boundary

Status: `CANONICAL_CONTENT_AUTHORITY`

Purpose: prevent visual-production agents from inventing personal facts simply to fill a page.

## Confirmed fixed facts currently allowed
- Couple names: `Shogo` / `Shiori`.
- Wedding date: `2026-10-24`.
- Venue identity: `ART GRACE PORTSIDE VILLA`, Yokohama, when the live project/source still confirms this exact spelling.

If a factual source later changes, update this file first.

## Not confirmed by this file
The following must remain `TBD` until supplied or verified from an authoritative project source:
- birthdays;
- hometowns;
- jobs;
- hobbies/favorites;
- exact relationship dates;
- first-date details;
- proposal details;
- exact memory destinations;
- favorite rankings/Best 5;
- Q&A questions and answers;
- wedding-day schedule times;
- dress-code statements;
- special-thanks copy;
- venue access text/address details;
- guest hashtag;
- photo-contest rules;
- final guest message.

## Placeholder policy
Allowed during layout:
- `TBD_PROFILE_FACT`;
- `TBD_MEMORY_CAPTION`;
- `TBD_Q1_ANSWER`;
- `TBD_TIME_01`;
- short clearly synthetic placeholder such as `ここにメッセージ`.

Not allowed:
- realistic-looking invented facts that could be mistaken for final copy.

## Figma policy
All factual/TBD content remains native editable text.

A page may reach `STRUCTURE_APPROVED` with TBD copy if hierarchy and geometry can be judged, but it may not reach `CONTENT_APPROVED` or `PRINT_READY` until the relevant facts are confirmed.

## Photo truth
A proxy photo is not evidence of a real event/location/person role.

Every photo slot must identify its state:
- `PROXY`;
- `REAL_CANDIDATE`;
- `FINAL_VERIFIED`.

Do not infer caption content from a proxy image.
