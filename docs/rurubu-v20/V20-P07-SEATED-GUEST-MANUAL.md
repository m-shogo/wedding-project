# V20 P07 — TODAY'S TRAVEL GUIDE / LOOK AROUND THE WEDDING

Status: `CANONICAL_P07_OVERRIDE`

This file supersedes the older schedule-first P07 section inside `V20-PAGE-MANUALS.md`.

## Page job

Guests are already seated. P07 should make the physical wedding around them more fun to notice, discuss and remember.

It is not a timetable, dress-code, access, seating or arrival page.

## First-read message

`TODAY'S TRAVEL GUIDE`

Second line / anchor:
`TODAY'S DESTINATION = YOKOHAMA / 2026.10.24`

Exact final Japanese wording remains editable/native.

## Reading path

1. large title colliding with background/travel art;
2. today's destination anchor;
3. one visually dominant discovery cluster;
4. 2–5 smaller `LOOK AROUND` discoveries;
5. 1 stronger `EDITOR'S PICK` detail;
6. micro discoveries / stamps / arrows;
7. a short line that connects today's venue back to the couple's journey.

## Content modules

### 1. `TODAY'S DESTINATION`

Keep:
- YOKOHAMA;
- 2026.10.24;
- one short editorial line.

Do not add fake flight/gate/boarding facts.

### 2. `LOOK AROUND`

Target 3–6 verified wedding details.

Possible categories only after confirmation:
- destination-themed tables/decor;
- flowers / venue decoration;
- travel-related paper/signage motifs visible in the space;
- cake/design detail;
- couple-made item;
- hidden/easter-egg-like detail that genuinely exists.

Each module should usually be 1–3 lines, not a paragraph.

### 3. `EDITOR'S PICK`

One stronger detail with slightly more space.

Must have a real reason/story. Do not create a feature just because the layout needs a large box.

### 4. `DESTINATION CLUSTER`

If multiple destination themes are verified, visualize them as unequal stamps/labels/illustrative fragments rather than a literal seating map.

This is editorial atmosphere and discovery, not navigation.

## Composition verb

`DISCOVER + CIRCLE + POINT + COLLIDE`

## Recommended silhouette

- title occupies/overlaps top-left to upper-center;
- one large irregular background/travel cluster occupies roughly 35–50% perceived page area;
- destination labels/stamps overlap the cluster and each other;
- one large editorial vessel sits partly on the cluster/photo/background;
- 2–4 smaller vessels appear in different silhouettes/sizes;
- arrows/lines point into actual content, not random decoration;
- one calm text-support field protects any longer explanation;
- some noncritical artwork may crop at bleed/edges.

Do NOT make six equal rounded cards.

## Strong overlap rule

Allowed and encouraged:
- title over illustration/background;
- vessel over destination cluster;
- stamp over vessel/photo;
- arrow/route across multiple layers;
- text-support object covering a large part of background art;
- labels partly hidden behind another layer if native text itself stays readable.

There is no maximum overlap percentage. Judge by hierarchy and readability.

## Information vessels

Do not default to rectangles.

Possible generated/composed vessels:
- irregular travel-magazine burst;
- torn/offset paper note;
- ticket-like text support without fake functional data;
- destination stamp shell;
- hand-drawn enclosed label;
- color slab with heavy keyline;
- photo-overlapping caption strip;
- map-fragment-like paper object;
- circular/oval editorial callout when the content fits.

The vessel shape must respond to the content and surrounding layers.

## Photography

Target: 0–2 photos.

P07 must work with zero photos.

A photo is used only if it helps guests recognize or understand a real visible detail. Do not add generic venue photography as filler.

## Native text contract

Keep native/editable:
- all destination/theme names;
- all wedding-detail descriptions;
- all factual claims;
- date/location;
- any couple-intention explanation.

Generated artwork contains no authoritative text.

## Explicit exclusions

- dress code;
- access/station/parking;
- reception/check-in instructions;
- RSVP;
- seating map/function;
- menu/drink list;
- ceremony/reception timetable as primary content;
- fake airline data;
- generic wedding etiquette;
- facts already useful only before arrival.

## Anti-AI / anti-UI failures

Reject when:
- all discoveries use identical cards;
- all destination labels have the same size and shape;
- the page resembles a dashboard/map app;
- decorative travel icons are evenly distributed to fill gaps;
- title, background and vessels do not physically interact;
- every detail is explained with the same copy length;
- the page could belong to any generic wedding because no real physical detail is referenced.

## Completion test

A guest should understand within 5 seconds that this page says “look around today's wedding,” then discover at least one verified detail they can physically notice around them.

The ideal response is curiosity/conversation, not logistical compliance.
