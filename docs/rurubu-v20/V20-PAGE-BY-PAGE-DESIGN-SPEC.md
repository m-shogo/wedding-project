# Rurubu WEDDING V20 — Page-by-Page Design Spec

Status: `CURRENT_CANONICAL_PAGE_DESIGN_SPEC / USER_CONFIRMED_2026-09-01`

Purpose: define all eight pages deeply enough that later ImageGen/Codex/Figma work executes a decided editorial design instead of inventing the page job.

This document is subordinate only to factual truth, print geometry, and `V20-CURRENT-PAGE-ARCHITECTURE.md`. If an older V20 design document conflicts with this page design spec, this spec wins for current page design behavior.

---

# 0. NON-NEGOTIABLE BOOK-WIDE CALIBRATION

## Visual target

The user-defined target is:

- `RURUBU FEEL = 100%`
- `EDITORIAL DENSITY = 75% OF MAXIMUM-CLUTTER RURUBU-LIKE TESTS`
- `READABILITY = HIGH`

Do **not** interpret `75%` as reducing the Japanese travel-magazine character to 75%.

Keep the full-strength editorial phenomena:
- giant display hierarchy;
- strong Japanese travel-magazine color energy;
- unequal photography;
- title/photo/frame collision;
- tactile paper/ticket/stamp/ribbon language;
- visible editorial authorship;
- asymmetric clustering;
- page-specific discoveries;
- active edges where appropriate.

Reduce only the overload:
- fewer tiny stickers;
- fewer simultaneous sub-features;
- fewer micro labels;
- fewer equal-weight photos;
- more visible photography;
- more local calm space;
- no gap-filling for its own sake.

`FULL-STRENGTH MAGAZINE CHARACTER, EDITED TO 75% INFORMATION LOAD.`

## Global hierarchy rule

Every page must have:
1. one unmistakable FIRST READ;
2. one dominant photo/visual event;
3. 1–3 secondary reads appropriate to the page;
4. optional micro discoveries only after hierarchy works;
5. at least one calm/readable field.

No page should require the reader to scan ten equal things before understanding the page job.

## Physical format

- A5 portrait;
- trim `148 × 210 mm`;
- 8 pages;
- working bleed `3 mm` until printer template overrides;
- authoritative/personal text native/editable;
- real photos individually replaceable;
- whole-page generation is art-direction proof only, not editable final master.

## Fixed event data

- wedding day: `2026.10.24`;
- numeric date: `20261024`;
- P08 decorative barcode digits: `2026102400000` exactly.

Do not recover `20161026`, `20261026`, or any other accidental date variant.

## Whole-book color family

Publication DNA may use:
- HOT PINK / coral for emotional/display emphasis;
- SUN YELLOW for highlight/burst;
- OCEAN CYAN/BLUE for travel/navigation energy;
- NAVY/INK for structure/readability;
- CREAM/PAPER/WHITE for calm support.

Do not use all five at equal area on every page. Each page chooses a dominant/support/accent relationship.

## Typography roles

- DISPLAY: bold, highly visible Japanese travel-magazine-style title art; generated art is allowed for non-variable display treatments.
- SECOND READ: short native or generated subtitle unit with clear hierarchy.
- BODY: native Japanese text, comfortable A5 reading size.
- CAPTION: native, short, attached directly to its photo/episode.
- META: small issue/folio/label text; never so numerous that meta becomes noise.

Working physical-size target:
- body roughly `8.5–10 pt` equivalent;
- Q&A answer roughly `8.5–9.5 pt` equivalent;
- captions roughly `7.5–8.5 pt` equivalent;
- do not shrink below comfortable print reading simply to preserve a vessel.

## Photo hierarchy rule

Avoid equal rectangles. Every photo-led page needs obvious roles:
- HERO;
- SUPPORT;
- DETAIL / SATELLITE.

The visual difference should be visible without reading captions.

## Generated-vs-native boundary

ImageGen/prepared art may create:
- title/masthead units;
- subtitle units;
- photo frames and paper backings;
- profile/story/memory/Q&A vessels;
- stamps/tickets/tape/ribbons;
- route/thread art;
- editorial arrows/icons;
- decorative edge clusters;
- micro ornament clusters.

Keep native/editable:
- names where factual;
- dates;
- profile facts;
- Q&A questions and answers;
- story copy;
- captions;
- thank-you copy;
- barcode human-readable digits;
- any changing factual/personal content.

## Density rhythm

Book-wide working density, where 100 means the previous maximum-clutter experiments, not visual authenticity:

- P01: `75/100`
- P02: `58–62/100`
- P03: `48–55/100`
- P04: `75/100`
- P05: `65–70/100`
- P06: `60–65/100`
- P07: `35–40/100`
- P08: `20–25/100`

Rurubu-like character remains 100% across the book; only information load changes.

# 1. SHARED Q&A SYSTEM — SIX QUESTIONS ACROSS THREE PAGES

## Placement

Exactly six Q&A slots are reserved as:
- P02: `Q1`, `Q2` — individual/personality/profile-oriented;
- P03: `Q3`, `Q4` — relationship/story-oriented;
- P06: `Q5`, `Q6` — daily-life/playful/future-oriented.

Actual wording and answers remain TODO until supplied/confirmed. Never fabricate answers.

## Shared-design ratio

`COMMON FORMAT = 70%`
`PAGE-SPECIFIC EXPRESSION = 30%`

The reader must instantly recognize all six as one recurring magazine feature, without feeling that the exact same component was pasted three times.

## Common 70% — must remain consistent

All Q&A modules share:
- same `Q1–Q6` badge family;
- same question-line typography hierarchy;
- same answer typography family/size logic;
- same base paper/cream vessel family;
- same keyline/shadow logic;
- same spacing logic between Q / question / answer;
- same small recurring icon or editorial notch motif;
- same answer-editability boundary;
- same maximum text budget philosophy.

Working copy budget per question:
- question: preferably about `8–24` Japanese characters;
- answer: preferably about `25–70` Japanese characters;
- if longer, edit copy before shrinking type.

## Page-specific 30%

### P02 Q&A variant — TIDY
- mostly straight alignment;
- clean compact paper/tag vessel;
- limited rotation;
- attached to profile/photo clusters;
- decorative detail restrained.

### P03 Q&A variant — EMOTIONAL
- same skeleton, but may use one softer torn-note / speech-note edge;
- slightly more narrative placement;
- may interrupt a story flow or overlap a photo margin;
- no comic-book speech-balloon look.

### P06 Q&A variant — PLAYFUL
- same Q badge and text hierarchy;
- slightly freer angle/placement;
- may use tape/arrow/paw/food/fun supporting cue;
- must still look like the same feature family, not a new sticker kit.

## Q&A anti-patterns

Reject:
- six identical boxes in identical positions;
- six visually unrelated Q&A styles;
- huge Q&A blocks that overpower the page topic;
- tiny answer text;
- generated gibberish baked into raster art;
- Q&A becoming the page's only content.

# 2. P01 — COVER / `るるぶ WEDDING`

## Page job

In three seconds:
1. this is a lively Japanese travel-magazine-like wedding special;
2. SHOGO & SHIORI are the protagonists;
3. the wedding date is `2026.10.24`;
4. the booklet looks exciting enough to open.

## Density

`75/100` information load.

This is the maximum cover energy allowed under the new 75% clutter ceiling. It should look visually powerful, not overloaded with tiny cover lines.

## First read

`るるぶ WEDDING` masthead.

The masthead should occupy roughly `22–32%` perceived visual weight depending on hero crop.

## Second read

Large couple HERO photo / environment.

## Required content

- `るるぶ WEDDING`;
- `SHOGO & SHIORI`;
- `2026.10.24`;
- `YOKOHAMA` only when compositionally useful;
- 1–2 short grounded cover hooks;
- optional one small issue/special marker.

Do not add a mini table of contents.

## Photo plan

Preferred:
- `1 HERO` couple/environment image;
- `1 SUPPORT` personality/detail image;
- optional `0–1 DETAIL` only if clearly improving balance.

Total target: `2–3 photos`, not a collage wall.

Perceived photo weight:
- HERO approximately `65–80%` of total photo weight;
- support clearly smaller.

## Composition silhouette

Working zone behavior:
- upper `5–28%`: masthead mass, allowed to crop/enter bleed;
- center `18–80%`: HERO image, dominant;
- one side or lower area: support image / cover hook cluster;
- lower `70–94%`: date/names/hook support as needed;
- 2–3 edges may be active, but not every edge.

## Overlap rule

At least one strong relationship:
`MASTHEAD ↔ HERO ↔ SUPPORT/HOOK`.

A flower/plane/route object may cross one photo/title boundary, but do not decorate every corner.

## Calm zone

Protect `SHOGO & SHIORI` and `2026.10.24` with enough contrast/negative space to read instantly.

## Generated production units

- `P01_MASTHEAD_UNIT`;
- `P01_SUPPORT_PHOTO_FRAME_UNIT`;
- `P01_DATE_ISSUE_VESSEL`;
- `P01_COVER_HOOK_UNIT_A/B` as needed;
- `P01_EDGE_TRAVEL_CLUSTER`;
- optional one feature burst.

## Native text

- names;
- date;
- location;
- cover hooks;
- issue/meta copy.

## Micro discoveries

Target only `3–7` meaningful small discoveries after primary hierarchy passes.

Examples:
- tiny airplane/route;
- one stamp;
- small tropical flower fragment;
- issue tab;
- tiny camera/travel symbol.

## Reject

- wedding invitation/card look;
- three equal photos;
- 8–12 tiny cover lines;
- every corner filled;
- micro-text as density substitute;
- masthead too small;
- generic floral border;
- repeated old SVG/icon-pack look.

## Pass condition

At thumbnail scale, the first two reads must be:
`るるぶ WEDDING` → couple HERO.

At A5 size, names/date remain immediately readable and photography still has room to breathe.

# 3. P02 — PROFILE / WHO WE ARE + Q1/Q2

## Page job

Make guests understand both people quickly without reading an employee-profile form.

## Density

`58–62/100`.

P02 is lively, but materially cleaner than P01/P04.

## First read

Working title behavior:
- Japanese primary or strong bilingual editorial title such as `ふたりのプロフィール` / `WHO WE ARE`;
- exact final copy may change, but title must feel like a people feature, not a generic top header.

## Core content

For each person:
- name;
- main portrait/personality photo;
- approximately `3–5` short grounded facts;
- no requirement to fill every possible category.

Shared:
- exactly two Q&A slots: `Q1`, `Q2`;
- optional one tiny shared-life marker only if real material supports it.

## Q&A semantic role

P02 questions should reveal the individual rather than repeat basic facts.

Examples of *question type only*, not locked copy:
- personal taste;
- hobby/holiday behavior;
- travel style;
- personality preference.

Do not invent actual answers.

## Photo plan

Preferred:
- `2 main portraits/personality photos`;
- optional `1 shared/detail photo`.

Total target: `2–3 photos`.

Do not add lifestyle photo after lifestyle photo merely to fill space.

## Composition silhouette

Avoid equal left/right employee cards.

Recommended behavior:
- title top-left or upper-offset;
- one portrait starts higher/larger;
- second portrait offset lower/right or opposite;
- fact clusters attach near each portrait;
- Q1/Q2 occupy separate but visually related locations, not one giant bottom questionnaire panel.

Suggested area balance:
- photography roughly `45–55%` perceived area;
- factual/profile copy roughly `20–25%`;
- Q&A roughly `12–18%`;
- remaining area is title, transitions and breathing room.

## Q&A variant

Use `TIDY` shared-Q&A variant.

- same core shell as P03/P06;
- mostly straight;
- compact;
- limited tape/rotation;
- visually integrated with profile clusters.

## Color job

- PAPER/CREAM dominant;
- OCEAN / HOT PINK can differentiate clusters but never identify gender by color alone;
- SUN used only for one highlight;
- NAVY/INK keeps text grounded.

## Generated production units

- `P02_TITLE_UNIT`;
- `P02_PROFILE_FRAME_A`;
- `P02_PROFILE_FRAME_B` materially different in geometry;
- `P02_FACT_LABEL_FAMILY`;
- `P02_QA_SHARED_SHELL_TIDY`;
- small annotation arrow/icon family;
- optional shared-life tag.

## Native text

- names;
- all profile facts;
- Q1/Q2 question and answer text;
- small captions.

## Micro discoveries

Target `3–6`, including Q badges themselves. Do not add 10 tiny icons.

## Reject

- groom card / bride card symmetry;
- blue=man and pink=woman without names;
- 7+ facts per person at final size;
- Q&A dominating half the page;
- timeline content;
- travel history;
- family/friend archive.

## Pass condition

A guest can understand both people in `10–15 seconds`, then discover Q1/Q2 without the page feeling crowded.

# 4. P03 — OUR STORY + Q3/Q4

## Page job

Tell how the relationship developed, emotionally and chronologically, without becoming a corporate timeline.

## Density

`48–55/100`.

This is the book's first deliberate reduction in density.

## First read

`OUR STORY` / relationship-story title + one emotional anchor image.

## Core content

Use `3–4` short story chapters, only from grounded facts:
- meeting / early outings;
- becoming a couple;
- proposal;
- marriage registration / arriving at the wedding.

Exact dates remain optional unless confirmed.

## Duplication boundary with P04

- P03 explains **what the Hawaii proposal meant in the relationship story**.
- P04 may show Hawaii as **one travel memory/destination**.
- Do not repeat the same long proposal copy on both pages.

## Q&A placement

Exactly two Q&A slots: `Q3`, `Q4`.

Semantic role:
- relationship perception;
- first impression;
- what they like/appreciate about each other;
- relationship-related reflection.

Actual questions/answers remain TODO until user supplies them.

## Photo plan

Preferred:
- `1 anchor` story photo;
- `1–2 support` memories.

Total target: `2–3 photos`, maximum 4 only if copy stays comfortably readable.

## Composition silhouette

Recommended flow:
- upper-left: title / intro;
- upper-right or center: anchor photo;
- middle: episode cluster 1–2;
- lower: episode cluster 3–4 / wedding arrival;
- Q3 and Q4 interrupt the story flow at two different points rather than forming one questionnaire block.

Use a subtle thread/route cue to imply progression, not a vertical timeline with six equal nodes.

## Q&A variant

Use `EMOTIONAL` shared-Q&A variant.

- same Q badge/typography/paper family as P02/P06;
- one softer/torn-note edge allowed;
- one may overlap a photo margin;
- one may sit inside a calm narrative field;
- no comic speech bubbles.

## Calm zone

Reserve one article/narrative field with comfortable line length. It should feel integrated, not like a detached white card.

## Color job

- CREAM/PAPER dominant;
- coral/pink for emotional highlight;
- OCEAN used sparingly as journey/thread cue;
- NAVY/INK body.

## Generated production units

- `P03_STORY_TITLE_UNIT`;
- `P03_EPISODE_VESSEL_A/B/C` with varied size, not identical cards;
- `P03_QA_SHARED_SHELL_EMOTIONAL`;
- `P03_ROUTE_THREAD_BACK/FRONT` restrained;
- optional proposal/wedding-arrival marker.

## Native text

- story chapters;
- dates when confirmed;
- Q3/Q4;
- captions.

## Micro discoveries

Target `2–5` beyond the Q&A badges.

## Reject

- 6–8 timeline nodes;
- exact dates invented to fill a timeline;
- travel-gallery behavior that belongs on P04;
- excessive decoration around emotional copy;
- huge proposal module that makes P04 redundant.

## Pass condition

Without reading dates, the reader still understands the emotional order. P02–P03 together clearly read as `WHO → HOW WE BECAME US`.

# 5. P04 — ALL TRAVEL MEMORIES / OUR JOURNEY

## Page job

Gather the couple's travel memories into the strongest interior travel-magazine page.

This is where the visual concept should feel most unmistakably like a real Japanese travel feature while preserving the new 75% density ceiling.

## Density

`75/100` — interior peak.

## First read

Large travel-feature title + dominant destination/HERO photo.

Working title behavior may use `旅の思い出` / `OUR JOURNEY`; exact copy can be refined later.

## Core content

Use only verified trips/photos.

Candidate destinations from grounded project context include:
- Okinawa;
- Korea;
- Hawaii;
- other verified trips supplied later.

Do not force a fixed number of destinations before the real photo pool is reviewed.

Recommended final content:
- `3–4 destination/memory clusters`;
- each cluster uses a place label + short memory/caption, not internet tourism copy;
- Hawaii/proposal may appear briefly as a travel memory while P03 owns the relationship-story explanation.

## Photo plan

Preferred total: `5–6 photos`.

Roles:
- `1 HERO` travel image;
- `2–3 SUPPORT` images;
- `1–2 DETAIL` images.

Hero should carry roughly `40–50%` of total photo weight.

Avoid 6 equal polaroids.

## Composition silhouette

Suggested behavior:
- top/upper-left: large page title, allowed to overlap HERO edge;
- central/one-side: HERO destination photo;
- support clusters orbit rather than line up;
- one route/thread may connect 2–4 real memory clusters;
- one medium destination feature may push toward the center fold;
- critical faces/copy stay out of fold risk.

P04 should look full, but approximately `25%` of the previous maximum-clutter micro-content is intentionally absent.

## Center-spread relationship with P05

P04–P05 form one broad `MEMORIES` chapter:
- P04 = `PLACES WE REMEMBER`;
- P05 = `PEOPLE WE REMEMBER`.

Use one subtle shared chapter device across both pages, such as:
- same small `MEMORIES` tab;
- related folio treatment;
- shared paper edge/color cue.

Do **not** require a literal airplane route crossing from P04 to P05.

## Color job

- photography dominant;
- OCEAN/cyan provides travel identity;
- SUN highlights one destination;
- HOT PINK/coral accents one emotional memory;
- CREAM provides caption calm;
- NAVY/INK maintains readability.

## Generated production units

- `P04_TRAVEL_FEATURE_TITLE_UNIT`;
- `P04_DESTINATION_VESSEL_A/B/C` varied silhouettes;
- `P04_HERO_FRAME_UNIT`;
- `P04_SUPPORT_FRAME_FAMILY`;
- `P04_ROUTE_BACK/FRONT` only if useful;
- `P04_STAMP_TICKET_CLUSTER`;
- `P04_EDGE_TRAVEL_CLUSTER`;
- shared `MEMORIES_CHAPTER_TAB` with P05.

## Native text

- destination names;
- actual memories/captions;
- dates only when useful and confirmed.

## Micro discoveries

Target `5–9` total, not 15–20.

These may include:
- one stamp;
- one ticket fragment;
- small camera/plane;
- destination number;
- tiny caption arrow;
- one cropped edge cue.

## Reject

- travel facts copied from the internet;
- equal destination cards;
- transit-map UI;
- all-polaroid scrapbook;
- 10+ tiny stickers filling cream areas;
- Hawaii-only page by accident;
- long proposal copy duplicated from P03.

## Pass condition

At thumbnail scale, P04 is the strongest interior travel page. At A5 size, each destination remains distinguishable and photos remain large enough to enjoy.

- filling all blank areas.

## Pass condition

P06→P07 visibly decelerates from fun to emotion, but P07 still looks intentionally designed as part of the same magazine.

# 9. P08 — MAGAZINE BACK COVER

## Page job

Behave like a real magazine back cover: restrained, intentional, and visually complete without becoming another content page.

The booklet has no meaningful thick physical spine at eight pages; treat the user's requested `背表紙` behavior as the **back cover** design.

## Density

`20–25/100` — quietest surface.

## First read

Background mood / one simple visual field.

## Core content ceiling

Prefer no more than `3–4 visible information objects` total:
- one small publication/issue mark;
- optional small `SHOGO & SHIORI` or `2026.10.24`;
- one tiny travel/wedding decorative mark;
- decorative barcode.

Do not include all optional items if they make the page busy.

## Barcode rule

Human-readable digits must be exactly:

`2026102400000`

Use a Code 128-compatible/decorative barcode treatment so the digits remain exact.

Do not silently alter the last digit for EAN-13 checksum compliance.

Recommended placement:
- conventional lower-right or lower area;
- enough quiet margin around barcode;
- human-readable digits directly below/near the bars;
- black/dark ink on light support for credible magazine behavior.

It is decorative/private-project metadata, not a real JAN/ISBN/product identifier.

## Background options

Choose one:
1. calm photo field;
2. quiet cream/paper field with restrained tropical/travel art;
3. deep navy/ink field with small cream editorial marks;
4. subtle continuation of P07 imagery, only if not repetitive.

Do not use a photo collage.

## Composition silhouette

Suggested:
- large quiet field `70–90%` of page;
- tiny issue mark top/side;
- barcode lower-right/lower;
- optional one micro motif in opposite corner for balance.

No large headline is required.

## Generated production units

- `P08_BACK_COVER_BACKGROUND` if not using real photo;
- `P08_SMALL_ISSUE_MARK`;
- `P08_MICRO_TRAVEL_WEDDING_MARK`;
- `P08_BARCODE_FRAME` / bars may be generated or programmatically rendered, but digits remain native/verified;
- optional tiny editorial line vessel.

## Native text

- `2026102400000`;
- date/names if used;
- any tiny non-legal editorial text.

## Reject

- fake real price;
- fake JAN/ISBN presented as valid commerce data;
- fake publisher/legal claims;
- QR without a real destination;
- long thank-you;
- feature hooks;
- 11 destinations;
- photo mosaic;
- P01-level color/noise.

## Pass condition

When the booklet is closed face-down, P08 looks like an intentional magazine back cover, not a missing page and not a ninth editorial feature.

# 13. IMAGEGEN → FIGMA PRODUCTION ORDER

For every page:

1. make one A5 full-page art-direction proof from this exact page spec;
2. judge first read, photo hierarchy, information load, and page uniqueness;
3. reject proofs that look like a wedding template, scrapbook kit, card grid or overfilled sticker page;
4. once approved, identify the 4–10 production units actually responsible for the successful look;
5. regenerate those units page-aware at high quality;
6. assemble bottom-to-top in Figma;
7. keep real photos replaceable;
8. keep factual/personal text native;
9. review page at thumbnail, normal reading size and A5 actual-size equivalent;
10. review physical spreads;
11. only then add final micro discoveries;
12. final print/preflight remains a separate gate.

Canonical layer stack:
1. PAPER / BASE
2. BACKGROUND / ENVIRONMENT
3. HERO REAL PHOTO
4. SUPPORT / DETAIL REAL PHOTOS
5. GENERATED PHOTO FRAMES / BACKINGS
6. ROUTE / THREAD BACK when relevant
7. GENERATED MAIN TITLE

9. GENERATED PROFILE / STORY / MEMORY / Q&A VESSELS
10. CAPTION / TICKET / STAMP / LABEL UNITS
11. ROUTE / THREAD FRONT when relevant
12. NATIVE AUTHORITATIVE TEXT
