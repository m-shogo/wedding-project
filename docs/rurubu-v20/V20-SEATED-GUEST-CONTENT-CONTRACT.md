# V20 Seated-Guest Content Contract

Status: `CANONICAL_READING_CONTEXT`

## 1. Reading context

V20 is primarily read AFTER guests have arrived and are seated at the wedding/reception venue.

It is not a pre-arrival invitation, access guide, logistics sheet or dress-code guide.

The booklet's job at the table is to:
- reward browsing while guests wait or chat;
- help guests know SHOGO and SHIORI better;
- create conversation starters at the table;
- show real memories and travel personality;
- make the wedding's travel concept more enjoyable once guests are physically inside it;
- provide small discoveries worth revisiting during the reception;
- close with warmth rather than instructions.

## 2. Content value test

Before any content block receives page space, ask:

1. Is this useful or enjoyable AFTER the guest is already seated?
2. Does it reveal something about the couple, their memories, or today's wedding concept?
3. Is it visually/editorially rewarding in a travel-magazine format?
4. Could it spark conversation between guests?
5. Is it non-duplicative with another paper item?
6. Is it based on verified content rather than generic wedding filler?

If the answer is mostly no, remove it.

## 3. Remove from V20 by default

The following do NOT deserve Rurubu page space unless a later concrete reason overrides this contract:

- dress code;
- access directions;
- nearest station / transit guidance;
- parking guidance;
- arrival/check-in instructions;
- gate/floor operational instructions;
- RSVP information;
- what to bring;
- pre-event reminders;
- generic wedding etiquette;
- transport-style fake flight data;
- reception logistics already obvious after seating.

Do not turn V20 into an information leaflet.

## 4. Duplication boundary with other wedding paper items

If a separate passport/menu/seating paper item already carries functional information, V20 should not repeat it merely to fill a page.

By default V20 does NOT duplicate:
- food menu;
- drink menu;
- seating chart;
- escort-card function;
- functional ticket data.

Those items may appear only as tiny visual/theme references if editorially useful, never as repeated utility content.

## 5. High-value seated content

Strongest content families:

### A. WHO ARE THEY?
- asymmetric couple profiles;
- real short facts;
- personality photographs;
- dogs/shared-life details when real assets exist.

### B. HOW DID THEY GET HERE?
- episode-led relationship story;
- early outings;
- proposal;
- registration → wedding arrival.

### C. WHERE HAVE THEY GONE TOGETHER?
- Okinawa;
- Korea;
- Hawaii;
- Yokohama as today's destination;
- strong real photos and short travel-memory copy.

### D. WHAT ARE THEY LIKE OFF THE MAP?
- candid life;
- funny/best shots;
- daily details;
- dogs;
- tiny real Q&A/facts if supplied.

### E. WHAT CAN GUESTS DISCOVER TODAY?
This replaces the schedule-first utility concept.

Recommended editorial idea:
`TODAY'S TRAVEL GUIDE / FIND THE JOURNEY AROUND YOU`

Possible verified content modules:
- today's table/décor destinations;
- travel-theme details guests can physically notice in the room;
- 2–4 wedding details with real meaning to the couple;
- small `LOOK AROUND` / `EDITOR'S PICK` discoveries;
- one simple venue/wedding photo or illustration only when it adds value.

This page should feel like a Rurubu feature guests can use from their seats, not a timetable.

### F. THANK YOU / CONTINUE THE JOURNEY
- personal closing copy;
- calm final photo;
- names/date;
- restrained travel continuation motif.

## 7. P07 recommended direction

### Primary concept
The guests have already arrived at today's destination. Let them discover how the TRAVEL theme exists around them.

### Strongest current candidate
`11 DESTINATIONS / TABLE JOURNEY`

Use the table-decoration/travel-destination concept as an editorial discovery feature if final table themes are confirmed.

Possible presentation:
- one playful world/route composition;
- destination labels arranged asymmetrically around it;
- one large `LOOK AROUND!` editorial headline;
- 2–4 small factual callouts about today's travel-theme details;
- optional close-up/detail image(s), not a gallery;
- bold labels may overlap map/photo/art strongly as long as text support preserves readability.

The point is not to tell guests where their seat is. The point is to make them notice and enjoy the themed room they are already sitting in.

### Table-theme content status
Current project context contains an 11-table destination/theme concept. Final wording/order must be confirmed before copy lock.

Do not invent countries, table assignments or decor details that are not final.

## 8. Schedule content disposition

Confirmed wedding times remain useful project facts, but they no longer automatically deserve a full V20 page.

Default V20 treatment:
- remove the schedule as the P07 primary structure;
- do not feature ceremony start/end times merely because they are known;
- if one time/date is editorially useful later, use it as minor native metadata only;
- dedicated timetable information belongs in another artifact if genuinely needed.

## 9. Content-density priority

When choosing between an instruction and a discovery, prefer the discovery after seating.

Examples:
- access map → remove;
- dress code → remove;
- table destination theme → keep;
- couple anecdote → keep;
- real funny photo → keep;
- generic wedding quote → remove;
- verified reason behind a wedding detail → keep;
- menu repeated from another booklet → remove.

## 10. Final principle

V20 should answer:

`WHO ARE THESE TWO?`
`WHAT HAVE THEY EXPERIENCED TOGETHER?`
`WHAT ARE THEY LIKE IN REAL LIFE?`
`WHAT CAN I NOTICE AND ENJOY TODAY?`

It should NOT answer questions the guest needed before arriving.
